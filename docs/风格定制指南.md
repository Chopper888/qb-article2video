# 风格定制指南

文章成片分成"框架"和"风格"两层（见 [架构说明](架构说明.md#框架与风格)）。框架决定"按什么流程把文章做成视频"，风格决定"做出来的视频长什么样、口播怎么说"。

本仓库带的是基础风格：白底、深灰字、单一蓝色强调、系统字体、普通白底字幕。这篇讲怎么把它换成你自己的风格，以及改完怎么验证、怎么避免白花钱。

## 风格由哪些文件组成

| 类别 | 文件 | 影响成片的哪部分 |
|---|---|---|
| 口播模板 | `engine/pipeline/vendor/zhongzhuanzhan/Article-to-Narration提示词模板-v2_3.md` | 口播稿的语气、长度、结构，也就是你听到的每一句话和字幕 |
| 步骤提示词 | `engine/pipeline/prompts/*.txt`（17 个） | 截图分析（哪句讲哪张图、停留多久、高亮什么）、截图旁的逐句标注、代码卡 / 表格卡的高亮 |
| 插画类型 | `engine/pipeline/vendor/wz-sp-ctsc/references/type-manifest.json` | 有哪几种插画、每种适合什么内容 |
| 插画提示词 | `engine/pipeline/vendor/wz-sp-ctsc/scripts/generate.py`、`title_generate.py` | 插画和标题图的画风、构图、配色、文字 |
| 配色 | `engine/R57-render-test/src/colors.ts` | 背景、正文、强调色、字幕框、进度条、章节标签 |
| 字体 | `engine/R57-render-test/src/fonts.tsx` | 画面上所有文字（字幕、标题、标注） |
| 字幕与版式 | `engine/R57-render-test/src/R125Root.tsx` | 字幕的字号、位置、样式，底部进度条，整体画面布局 |
| 各类卡片 | `engine/R57-render-test/src/ST3Components.tsx` | 标题卡、代码卡、终端卡、表格卡 |
| 截图镜头 | `engine/R57-render-test/src/shots/ScreenshotScene.tsx` | 截图上的高亮框、箭头、侧栏标注的样式 |

可以粗分成两类：

- **提示词类**（口播模板、步骤提示词、插画类型和插画提示词）：改的是"说什么、画什么"。它们会进付费请求的缓存键，改了之后相关请求要重新付费。
- **渲染类**（配色、字体、字幕版式、卡片、截图镜头）：改的是"画面怎么摆、长什么样"。只影响本地渲染，重新渲染不花钱。

## 例子一：换强调色

基础风格的强调色是蓝色 `#2F6FEB`，比如想换成绿色 `#16A34A`。

**1）改渲染层配色**：`engine/R57-render-test/src/colors.ts`

```ts
export const COLOR_ACCENT = "#16A34A";  // 强调色
export const COLOR_TAG_BG = "#E8F6EE";  // 章节标签底（强调色的浅色版）
export const COLOR_TAG_FG = "#16A34A";  // 章节标签字
```

注意保持 `export const 名字 = "#RRGGBB";` 这种写法：引擎的成片核对（`engine/pipeline/engine/frame_check.py`）会按这个格式从文件里读 `COLOR_INK` 等颜色。

**2）截图高亮框的颜色**：高亮框的颜色在引擎排镜头时就写进场景数据，渲染层只是兜底。要一起改：

- `engine/pipeline/shot_director.py` 里的 `COLOR_CLEAN`（高亮框颜色）和 `COLOR_ANNOTATED`（箭头颜色）；
- `engine/R57-render-test/src/shots/ScreenshotScene.tsx` 里的 `HIGHLIGHT_BLUE`、`ARROW_BLUE`（场景数据里没写颜色时的兜底）。

**3）成片核对用的特征色**：`engine/pipeline/engine/frame_check.py` 里的 `ACCENT_RGB` 要改成新颜色的 RGB（这里是 `(0x16, 0xA3, 0x4A)`）。它用强调色来判断"代码卡 / 终端卡 / 表格卡有没有真的上屏"，不改的话检查报告可能误报。

**4）插画里的颜色**：插画是图片模型画的，颜色写在插画提示词里（`generate.py`、`title_generate.py` 拼装提示词的部分）。只改上面三处的话，字幕、卡片、高亮框会变绿，插画仍是原来的配色。要统一，就把插画提示词里对强调色的描述也改掉——这会让插画全部重新生成，见 [别让缓存全部失效](#别让缓存全部失效)。

**5）让已有文章用上新颜色**：

```powershell
# 只改了 1）～3）：从 S7 重新排镜头并渲染。提示词没变，S7、S8 的请求都命中缓存，不花钱
python -m pipeline.engine run --work-root "<工作目录>" --article "<文章文件夹名>" --runtime-dir "<仓库路径>\engine\R57-render-test" --from S7

# 只改了 colors.ts：只重新渲染
python -m pipeline.engine run --work-root "<工作目录>" --article "<文章文件夹名>" --runtime-dir "<仓库路径>\engine\R57-render-test" --from S10
```

## 例子二：换字体

基础风格用系统字体（`fonts.tsx` 里的 `TITLE_FONT` 是一串系统字体名）。想换成自己的字体文件：

**1）放字体文件。** 引擎渲染时会把运行时目录下的 `fonts/LXGWWenKai-Regular.ttf` 复制进每篇文章的渲染工程。这个文件名是代码里固定的（`engine/pipeline/engine/paths.py` 的 `FONT_REL`），放任何 TrueType 字体都可以，只是名字要叫这个。从源码运行、`--runtime-dir` 指向 `engine\R57-render-test` 时，放在：

```
engine\R57-render-test\fonts\LXGWWenKai-Regular.ttf
```

字体文件请确认授权允许你这样使用和分发。

**2）改 `engine/R57-render-test/src/fonts.tsx`**，加载这个文件并把它排在字体栈第一位：

```tsx
import React from "react";
import { continueRender, delayRender, staticFile } from "remotion";

export const TITLE_FONT =
  '"MyFont", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif';

// 字体加载完之前先暂停渲染，避免前几帧用了系统字体
const handle = delayRender("加载字体");
const face = new FontFace("MyFont", `url(${staticFile("fonts/LXGWWenKai-Regular.ttf")}) format("truetype")`);
face.load().then(() => {
  document.fonts.add(face);
  continueRender(handle);
}).catch((err) => {
  console.error("字体加载失败", err);
  continueRender(handle);
});

export const FontFaces: React.FC = () => null;
```

**3）标注排版会自动跟上。** 截图旁的标注要按字宽排版，引擎量宽时优先用运行时目录里同一个字体文件（`engine/pipeline/shot_annotate.py` 的 `font_path`），没有才用系统字体。所以换完字体，标注的换行、截断会按新字体重新算。

**4）让已有文章用上新字体**：

```powershell
python -m pipeline.engine run --work-root "<工作目录>" --article "<文章文件夹名>" --runtime-dir "<仓库路径>\engine\R57-render-test" --from S7
```

截图型文章的逐句标注会按新字宽重新排；字宽变化导致某些标注要重新生成时，会有少量 DeepSeek 费用。理论型文章只用 `--from S10` 即可。

## 改提示词的规则

以公开版文件为准，改的时候守住下面几条，流程就不会断。

### 占位符

- 提示词里的占位符有两种写法：`{名字}` 和 `{{名字}}`（具体用哪种，看文件里原来怎么写）。
- 代码用**纯文本替换**把它们换成实际内容（文章原文、口播句、图片说明、停留秒数等），不是 Python 的 `format`，所以提示词里出现其他花括号不会出错。
- **原有占位符要原样保留**：名字一个字都不能改。删掉某个占位符，那份信息就不会再交给模型。
- **自己新加的占位符不会被填**：代码只替换它认识的那几个，新名字会原样留在提示词里发给模型。要加新信息，得同时改调用它的代码（见 `engine/pipeline/shot_ai.py`、`shot_annotate.py` 等）。

### 输出格式

- 步骤提示词几乎都要求模型**返回 JSON**。代码会先去掉 ```` ```json ```` 包裹再解析，然后按字段校验（例如字段类型、数组长度、文字是否来自口播原文）。
- **字段名和结构要和原文件保持一致**。可以改要求、改语气、加例子，但别改输出的 JSON 长什么样。校验不过，代码会重试，再不行就按兜底处理（比如不并列、不高亮），效果会变差。
- 改之前先看调用它的代码是怎么校验的：在 `engine/pipeline/` 下搜提示词文件名即可找到。

### 口播模板

- 模板里以 `## User Prompt` 开头的那一行把模板分成两半：上面作为系统提示，下面作为用户提示。没有这一行，整份模板都作为系统提示。
- `{{source_article}}` 会被替换成文章原文；模板里没有它时，原文接在用户提示末尾。
- **口播的输出格式要保留**：原文每个标题用 `【】` 单独占一行，下面跟口播正文。后面的分组（S2）靠以 `【` 开头的行识别章节标题，进度条、章节标签也来自这里；这些行不会被朗读。

### 插画类型与插画提示词

- `type-manifest.json` 的 `types` 是一个列表，每项有 `id`、`name`、`desc`。编排时 DeepSeek 按 `desc` 给每段内容挑类型。
- `generic` 是兜底类型（挑不出来时用），**不要删**。
- 新加一种类型时，在 `generate.py` 的 `TYPE_OPENING` 里给它加一句用途说明；不加也能用，会套通用开头。
- 插画的画风、构图、配色、字数要求都在 `generate.py`（内容插画）和 `title_generate.py`（标题图）拼装提示词的函数里。

## 改完怎么验证

建议按这个顺序，从便宜到贵：

1. **先用短文章。** 仓库自带一篇示例文章 `engine/R168/示例文章-如何整理电脑桌面.md`，也可以用你自己的一篇短文。
2. **导入并估算。** `import` 之后先 `estimate`，看费用范围是否合理：

   ```powershell
   python -m pipeline.engine import --work-root "<工作目录>" --input "<仓库路径>\engine\R168\示例文章-如何整理电脑桌面.md"
   python -m pipeline.engine estimate --work-root "<工作目录>" --article "<文章文件夹名>"
   ```

3. **带上限出片。** 第一次跑新风格，上限设低一点：

   ```powershell
   python -m pipeline.engine run --work-root "<工作目录>" --article "<文章文件夹名>" --runtime-dir "<仓库路径>\engine\R57-render-test" --max-cost-cny 5
   ```

4. **看检查报告。** 打开 `<工作目录>\<文章文件夹名>\10-报告\检查报告.md`，第一行是总体结论。改了配色、字体、版式后，重点看"要素未上屏"有没有新增（通常是 `frame_check.py` 里的颜色没同步）。
5. **看成片。** 检查报告只能查出"有没有、对不对得上"，好不好看还得自己看。

## 别让缓存全部失效

每个付费请求都按"请求内容"缓存（模型名 + 完整提示词 + 参数）。提示词改一个字，用到它的请求就全部不再命中缓存，要重新付费。几个容易踩的坑：

| 改了什么 | 会重新付费的部分 | 怎么省 |
|---|---|---|
| 口播模板 | 已有文章不会自动重做（口播有定稿锁）。用 `--unlock-narration` 重做时：口播、配音，以及后面所有依赖口播的请求 | 先用短文章试好模板，再用到长文章上 |
| 步骤提示词 | 用到这份提示词的那一类请求（例如只改逐句标注，就只有标注重做） | 一次只改一份，改完马上用短文章验证 |
| `type-manifest.json`、`type_match.py`、`generate.py`、`orchestrate.py` | 编排时的插画决策：这几个文件的内容指纹是缓存键的一部分，文件里改任何地方都会让这一类缓存失效 | 改插画相关文件时集中改，一次验证 |
| 插画提示词的拼装（`generate.py`、`title_generate.py`） | **全部插画重新生成**，是最贵的一项 | 先用 `estimate` 看出图张数，再决定 |
| 配色、字体、字幕版式、卡片、截图镜头 | 不花钱（字体可能引起少量标注重做） | 用 `--from S10` 只重新渲染 |

还有两点：

- 已经跑完的步骤，引擎按输入文件判断要不要重跑，**不检查提示词有没有变**。所以改了提示词后，要用 `--from <步骤>` 让已有文章从那一步重做（口播模板用 `--unlock-narration`）。
- 想确认改动后是不是全部命中缓存：加 `--no-paid` 跑一遍。只要遇到一个缓存命中不了的付费请求，引擎就会停下，并在失败信息里写明是哪一步、哪类请求，一分钱不花。
