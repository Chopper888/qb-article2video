## 桌面应用与引擎的分工

| | 桌面应用（`app/`） | 引擎（`engine/`） |
|---|---|---|
| 负责什么 | 界面、密钥存储、任务列表、成片库、进度展示 | 导入、11 步出片、缓存、续跑、检查报告 |
| 密钥 | 用系统加密（Electron safeStorage）保存在本机；启动引擎时以环境变量传给引擎子进程，不落盘、不写日志 | 只从进程环境变量读取，不读 `.env`、不写盘 |
| 怎么通信 | 以子进程方式运行 `python -m pipeline.engine <命令> …`，逐行读取引擎的标准输出 | 标准输出只输出"一行一个 JSON"的事件（步骤开始、进度、完成、失败、结束），其他日志写到标准错误和文章的 `logs/` |
| 能不能单独用 | 不能，需要引擎 | 能，命令行即可完整出片，Agent 也是这样调用 |

所以：只要引擎的命令行和事件格式不变，界面和引擎可以各自修改；想把文章成片接进别的工具，直接调用命令行即可。

## 工作目录结构

`--work-root` 下每篇文章一个文件夹，名字是 `<4 位序号>-<标题前 12 个字符>`。文件夹里按步骤分目录：

| 目录 / 文件 | 由谁写 | 放什么 |
|---|---|---|
| `00-输入/` | 导入、S0 | `文章.md`、`图片和附件/`（原文图片）、`来源.json`（来源与可选的指定类型）、`类型判断.json`、识图缓存 |
| `01-口播/` | S1 | `narration.txt`（口播稿）、命令重写记录、`定稿锁.json`（S1～S3 都成功后写入） |
| `02-分组/` | S2 | `groups_raw.json`（切句、分组、章节标题） |
| `03-配音/` | S3 | `audio/narration.wav`、`sentences.json`（逐句逐字时间）、配音缓存 |
| `04-对齐/` | S4 | `alignment.json`（组级时间）、`char_times.json`（字级时间） |
| `05-截图分析/` | S5、S6（仅截图型） | 图片定位、截图分组、图句匹配、停留判断、镜头计划及其缓存 |
| `06-编排/` | S5（理论型）、S6、S7 | `出图需求.json`（每张插画画什么）、截图型的 `shots_plan.json`（最终时间轴）、编排缓存 |
| `07-出图/` | S8 | `images/*.png`、`manifest.json`、`缺图.json`（多次失败的图）、出图缓存 |
| `08-场景/` | S9 | `video_data.json`（逐帧场景数据）等 |
| `09-成片/` | S10 | 本篇独立的渲染工程 `render/` 和成片 mp4 |
| `10-报告/` | S9、S10 | `检查报告.md`（给人看）、`检查结果.json`（给程序读） |
| `logs/` | 引擎 | 每次运行的日志、各项核对表 |
| `进度账本.json` | 引擎 | 每一步的状态、输入指纹、产物清单、花费，续跑靠它判断哪些步骤可以跳过 |

几个约定：

- **缓存放在文章文件夹里**（各步骤目录下的 `cache/`），按请求内容算键。把整个文章文件夹拷到别处，缓存跟着走。
- **每一步轮到时重新判断要不要跑**：上游这一轮产出了新内容，下游在同一次运行里跟着重做；上游没变就跳过。
- **同一篇文章同一时刻只能有一个引擎在跑**（`.run.lock`），第二次启动会以退出码 4 退出。

## 框架与风格
