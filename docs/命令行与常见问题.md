# 命令行与常见问题

引擎可以脱离桌面应用单独运行。所有命令在 `engine` 目录下执行，入口是：

```powershell
python -m pipeline.engine <子命令> [参数]
```

运行前先把密钥加载进当前终端（见 README 的 [配置密钥](../README.md#方式二从源码运行)）。

## 子命令

| 子命令 | 做什么 | 会不会花钱 / 写盘 |
|---|---|---|
| `import` | 导入文章（飞书链接、本地 `.md`、文件夹、`.zip`），做输入检查，不执行任何步骤 | 不花钱；会建文章文件夹 |
| `estimate` | 估算这篇文章接下来要花多少钱（给出低 / 高两个数，并标出缓存能省多少） | 不联网、不要密钥、不写盘 |
| `run` | 出片。可续跑：已完成的步骤自动跳过 | 会调用付费服务 |
| `plan` | 列出 `run` 时每一步将执行还是跳过、为什么 | 只读 |
| `status` | 按进度账本汇报每一步的状态、耗时、产物 | 只读 |
| `check-keys` | 检测各服务的密钥是否可用（只调不计费的接口） | 不花钱 |

## 参数表

### `run`

| 参数 | 说明 |
|---|---|
| `--work-root` | **必填**。工作根目录，每篇文章一个子文件夹 |
| `--article` | 已有文章文件夹名。与 `--input` 二选一 |
| `--input` | 飞书链接，或本地的文件夹 / `.zip` / `.md`。先导入（同一来源已导入过则复用），再出片。与 `--article` 二选一 |
| `--delivery-root` | 成片交付目录。成片会复制到 `<delivery-root>\<文章文件夹名>\<文章文件夹名>.mp4`；不传则只留在文章的 `09-成片\` |
| `--runtime-dir` | 运行时目录（其下要有含 `remotion` 的 `node_modules`）。默认 `<work-root 的上一级>\_runtime`；从源码运行时指向 `engine\R57-render-test` |
| `--tmp-dir` | 临时目录（会把 TEMP / TMP 指向它） |
| `--max-cost-cny` | 本篇费用上限（元）。不传时读环境变量 `A2V_MAX_COST_CNY`，再没有就用默认 50。上限按整篇文章累计，续跑时接着算 |
| `--from` | 从某一步开始重做，连同依赖它产出的下游步骤，例如 `--from S7` |
| `--to` | 跑到某一步就停，例如 `--to S3` |
| `--no-paid` | 禁止一切付费调用：只能用缓存，遇到要花钱的请求就停下 |
| `--unlock-narration` | 删除口播定稿锁，重新生成口播、分组、配音 |
| `--accept-narration-edit` | 你手改了 `01-口播\narration.txt` 后用：保留你的口播，只重做分组和配音，然后重新落锁 |
| `--content-type` | 配合 `--input`：`auto`（默认，自动判断，有图时要付费识图）/ `theory`（理论型）/ `screenshot`（截图型）。指定后 S0 不再识图 |
| `--refetch` | 配合 `--input`：飞书文章重新抓取原文；本地 md 强制把 md 和图片重新同步进原文件夹 |
| `--title-chars` | 配合 `--input`：新文件夹名里取标题的前几个字符（1～60，默认 12） |
| `--stub` | 仅供开发测试：用桩代替真实付费调用。有桩结果的文章不允许出片 |

### `import`

`--work-root`（必填）、`--input`（必填），以及 `--refetch`、`--content-type`、`--title-chars`，含义同上。

### `estimate`

`--work-root`、`--article`，都必填。

### `plan`、`status`

`--work-root`、`--article`（都必填），其余同 `run` 的 `--runtime-dir`、`--delivery-root`、`--tmp-dir`。

### `check-keys`

`--services`：逗号分隔，可选 `deepseek`、`ark`、`tts`、`runninghub`、`feishu`；不传则全部检测。

### 环境变量

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY`、`ARK_API_KEY`、`MODEL_SPEECH_API_KEY`、`RUNNINGHUB_API_KEY` | 四个付费服务的密钥。只在这一轮真要调用对应服务时才检查 |
| `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 导入飞书文档时需要 |
| `A2V_TTS_SPEAKER`、`A2V_TTS_RESOURCE_ID` | 配音音色和资源编号，见 [公共音色与复刻音色](#公共音色与复刻音色) |
| `A2V_MAX_COST_CNY` | 费用上限的默认值（`--max-cost-cny` 优先） |

## 退出码

| 退出码 | 含义 | 该怎么处理 |
|---|---|---|
| `0` | 成功，检查报告无标红 | 成片可用 |
| `1` | **已出片**，但检查报告有标红 | 打开 `10-报告\检查报告.md` 看标红项，再看成片对应时间点。见 [检查报告标红怎么办](#检查报告标红怎么办) |
| `2` | 某一步执行失败 | 看最后一条事件里的 `error_kind` 和 `service`：余额不足就充值、网络问题稍后重试、费用超限就调高上限。处理后直接再跑一次，会从失败的那一步接着跑 |
| `3` | 被中断（Ctrl+C 或应用里点了停止） | 当前步骤保持未完成，下次运行重跑这一步 |
| `4` | 参数或配置错误：参数写错、缺密钥、文章文件夹不存在、输入有问题、同一篇文章已经有引擎在跑、口播已定稿但文件被改过 | 按提示修正后再跑。这类错误发生时还没有花钱 |

`error_kind` 的取值：`input_invalid`（输入有问题）、`key_missing`（缺密钥）、`key_invalid`（密钥错误或无权限）、`balance_insufficient`（余额不足）、`network`（网络问题，已自动重试过）、`service_error`（服务返回错误）、`cost_limit`（超出费用上限）、`paid_blocked`（`--no-paid` 下遇到要花钱的请求）、`render_failed`（渲染失败）、`disk_full`（磁盘满）、`already_running`（这篇正在跑）、`interrupted`（中断）、`internal`（其他）。

## 续跑与重做

- **直接再跑一次就是续跑。** 引擎按进度账本和输入文件判断每一步要不要跑：已完成且输入没变的跳过；上游这一轮产出了新内容，下游在同一次运行里跟着重做。
- **想从某一步重做**：`--from <步骤>`。例如改了配色只想重新渲染用 `--from S10`；改了截图标注的提示词用 `--from S7`。重做时请求内容没变的部分仍然命中缓存。
- **只跑前半段**：`--to <步骤>`。例如 `--to S3` 先把口播和配音做出来，听一遍再继续。
- **口播定稿锁**：S1～S3 都成功后会写 `01-口播\定稿锁.json`，之后口播、分组、配音一律跳过（`--from S1` 也不会重做它们）。
  - 想换一版口播：`--unlock-narration`。
  - 想自己改口播：直接编辑 `01-口播\narration.txt`，然后加 `--accept-narration-edit` 运行，会保留你的版本、重新配音。
  - 改了原文（`00-输入\文章.md` 或重新导入）：口播没人改过时，引擎会自动解锁、按新原文重做；你改过口播时会以退出码 4 停下，让你在上面两个参数里选一个。
- **先看再跑**：`plan` 会列出每一步这次是执行还是跳过、原因是什么。

## 输出格式

- 标准输出只有事件，**一行一个 JSON**，字段包括 `event`、`step`、`message`、`seq`、`time`。事件类型：`input_resolved`、`input_problems`、`step_start`、`step_progress`、`step_done`、`step_skip`、`step_fail`、`narration_unlocked`、`plan`、`status`、`estimate`、`key_check`、`run_done`。
- 每次运行以一条 `run_done` 结束，带 `exit_code`；出片成功时带成片路径 `delivery_path` 和检查结果文件 `report_json`，失败时带 `error_kind`、`service`。
- 其他日志写到标准错误，同时保存在文章的 `logs\run-<时间>.log`。

## 常见问题

### 一篇大概多少钱？

看文章长度和截图数量。安装包（完整风格）的实测：2 分钟左右的截图型短文约 ¥6，4 分钟约 ¥5.5，13 分钟约 ¥18，25 分钟约 ¥29（见 README [实测数据](../README.md#实测数据)）。出图（每张插画一次请求）和截图分析（截图越多请求越多）是主要开销。

想知道某一篇的数字，导入后跑 `estimate`，它会给出低 / 高两个数，并按服务分开列出。

### 为什么安装包的效果比源码好？

框架是同一套，区别在风格：安装包里是作者打磨过的提示词、口播模板、插画风格、配色字体和版式；本仓库带的是基础风格，能完整出片，但画面朴素。想做自己的风格，见 [风格定制指南](风格定制指南.md)。

### 密钥存在哪里？安全吗？

- **安装包**：密钥用 Windows 系统加密（Electron safeStorage）后保存在本机的应用数据目录里。只在启动引擎时解密，以环境变量交给引擎；不写进日志，界面上只显示是否已填写。
- **源码运行**：引擎只从当前终端的环境变量读取密钥，不读 `.env` 文件、不把密钥写盘。渲染子进程启动前会从环境里去掉这些密钥。`.env` 已在 `.gitignore` 里，不会被提交。
- 密钥只发给对应服务的官方接口。

### Windows 提示「Windows 已保护你的电脑」？

安装包没有做代码签名（打包配置里 `signExecutable: false`），首次运行时 SmartScreen 会拦一下。点「更多信息」→「仍要运行」即可。

### 飞书导入要怎么授权？

1. 在 [飞书开放平台](https://open.feishu.cn/app) 创建一个企业自建应用，拿到 App ID 和 App Secret。
2. 给应用开通读取云文档、知识库内容、下载文档图片的权限（具体权限名以飞书开放平台为准），并发布应用版本。
3. 把要导入的文档授权给这个应用（在文档的分享 / 协作设置里添加该应用）。
4. 在应用设置里填 App ID / App Secret，或设置环境变量 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`。

引擎只用应用身份只读访问飞书，不写飞书。没有权限时导入会以退出码 4 停下，`error_kind` 为 `key_invalid`。只用本地 Markdown 可以不配飞书。

### 公共音色与复刻音色

- **默认用公共音色**（`zh_female_shuangkuaisisi_uranus_bigtts`），需要在火山引擎开通「语音合成大模型」。
- **想用自己的声音**：在火山引擎开通「声音复刻」，录好音色后把音色编号（`S_` 开头）填到设置里，或设环境变量 `A2V_TTS_SPEAKER`。引擎会按编号自动选对应的资源编号；需要时可以用 `A2V_TTS_RESOURCE_ID` 手动指定。
- 配音缓存按音色区分。已经定稿的文章换音色后，要加 `--unlock-narration` 才会重新配音；原文和口播模板没变时，口播请求会命中缓存，只有配音重新花钱。

### RunningHub 余额不足会怎样？

出图（S8）会停下，退出码 2，`error_kind` 为 `balance_insufficient`。已经出好的图都在缓存里，已提交的任务号也记在账本里。充值后直接再跑一次，只会补剩下的图，不重复花钱。

其他服务（DeepSeek、方舟、豆包语音）余额不足也一样：在用到它的那一步停下，充值后续跑。

如果某张图是因为服务端出错连续失败（不是余额问题），引擎会重试几次，还不行就记为缺图、接着出别的图，成片里由前后画面补位，检查报告里标红。下次运行只为缺的图重新出图。

### 检查报告标红怎么办？

标红不代表没出片，退出码 1 时成片已经生成好了。打开 `10-报告\检查报告.md`：

- 第一行是总体结论；接着列出每个标红项，大多带时间点（分:秒），对着成片看那一处。
- 每项后面的明细在 `logs\` 下对应的核对表里。
- 常见的几类：
  - **插画缺失**：出图多次失败，直接再跑一次会重新出这几张。
  - **要素未上屏**：代码卡 / 终端卡 / 表格卡在成片里没检测到。如果你改过配色，先检查 `frame_check.py` 里的颜色有没有同步（见 [风格定制指南](风格定制指南.md#例子一换强调色)）。
  - **配音漏读**：配音里少了某段文字。可以 `--unlock-narration` 重新配音，或手改口播后 `--accept-narration-edit`。
  - **口播仍念命令**：口播里还有念命令行的句子，可以手改 `narration.txt` 后用 `--accept-narration-edit`。
  - **成片声音与本次配音不符**：成片里装的不是这次的配音，用 `--from S10` 重新渲染。
- 看过觉得可以接受，就直接用；"提示"类条目不影响退出码，只是提醒。

### 报「该文章正在运行」？

同一篇文章同一时刻只允许一个引擎在跑。如果确认没有在跑（例如上次被强制关掉），再运行一次即可，引擎会清掉过期的锁。
